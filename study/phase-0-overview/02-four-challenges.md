# 四大挑战深入

> 阶段 0 · 第二篇
> 目标：理解分布式系统**所有协议**都在解决的四个根本问题。

---

## 挑战一：网络不可靠（Network Unreliability）

### 问题
机器之间通过网络通信，网络会：
- **延迟**：消息要花时间才能到
- **丢包**：消息可能半路丢了
- **乱序**：先发的消息可能后到
- **重复**：同一个消息可能收到多次（重传导致）

### 后果
- 你发了一个请求，不知道对方有没有收到
- 你不知道对方是"处理慢"还是"死了"

### 怎么应对
| 手段 | 解决什么 |
|---|---|
| **超时重传** | 丢包 |
| **序列号** | 乱序、重复 |
| **幂等设计** | 重复请求 |
| **任意延迟假设** | 异步网络模型，不假设消息能在 X ms 内到达 |

---

## 挑战二：部分失败（Partial Failure）

### 问题
单机要么全好要么全坏；分布式是**部分机器好，部分坏**。

### 后果
- 你调用一个服务，它可能：正常返回、超时、崩溃、返回错误
- 你不知道调用方是成功了还是失败了
- 集群里有一部分机器能服务，一部分不能

### 怎么应对
| 手段 | 解决什么 |
|---|---|
| **多数派（Quorum）** | 少数派挂了不影响正确性 |
| **复制（Replication）** | 一台挂了别的还能顶上 |
| **超时检测** | 怎么知道机器死了 |
| **优雅降级** | 部分功能不可用时还能提供核心功能 |

---

## 挑战三：时钟漂移（Clock Drift）

### 问题
每台机器都有自己的时钟，但：
- 时钟会漂移，不同步
- NTP 同步也有误差
- GC 暂停会让"时间停止"

### 后果
- 你以为"过了 5 秒"，实际可能是 5.5 秒
- 你以为 A 操作在 B 之前，实际可能不是
- 用时间来判断"谁先谁后"不可靠

### 怎么应对
| 手段 | 解决什么 |
|---|---|
| **逻辑时钟（Logical Clock）** | 用计数器代替真实时间 |
| **向量时钟（Vector Clock）** | 追踪因果关系 |
| **TrueTime（Google）** | GPS + 原子钟，时间区间而非精确值 |
| **不依赖绝对时间** | 用消息来回判断，不用 timeout 判断正确性 |

---

## 挑战四：并发与顺序（Concurrency and Ordering）

### 问题
多个操作同时发生，谁先谁后？
- 两个客户端同时写同一个 key
- 两个节点同时以为自己是 leader
- 一个操作跨多个分片，部分成功部分失败

### 后果
- 数据不一致
- 脑裂（两个 leader 同时工作）
- 读不到正确的值

### 怎么应对
| 手段 | 解决什么 |
|---|---|
| **共识协议（Consensus）** | 所有节点按同一顺序执行 |
| **选主（Leader Election）** | 同一时间只有一个 leader |
| **分布式事务（Transactions）** | 跨分片操作原子性 |
| **一致性模型（Consistency Model）** | 定义"读到的数据应该有多新" |
