# SUNDR (2004) 精读

> 论文：<https://pdos.csail.mit.edu/6.824/papers/sundr.pdf> ｜ 对应 LEC 20（Fork Consistency）

---

## 1. 一句话问题

**如果文件服务器本身是恶意的（被攻陷、或想篡改历史），客户端怎么知道自己看到的文件系统版本没被改过？**

SUNDR 用 **fork consistency（分叉一致性）** 解决：服务器可以分叉（给出不同版本），但一旦分叉，客户端能**检测到**。

---

## 2. 核心思路

- 客户端对每次写生成一个**哈希链**（类似区块链）：
  - 新版本 = Hash(旧版本哈希 + 新内容 + 客户端签名)
- 服务器只负责存这些哈希和数据。
- 如果服务器想篡改历史，必须重算所有后续哈希，但客户端有旧版本哈希，一对比就发现。
- 如果服务器给不同客户端不同版本，**分叉会被检测到**。

---

## 3. Fork Consistency 是什么？

- **线性一致**：所有客户端看到同一个历史。
- **Fork 一致**：服务器可以给不同客户端不同历史，但**一旦分叉，客户端能检测到**。
- 比线性一致弱，但比最终一致强（因为有可检测性）。

---

## 4. 与 Git 的相似性

- Git 的 commit 也是哈希链。
- 你 clone 一个仓库后，如果服务器偷偷改历史（force push），你的本地 commit hash 对不上，就发现了。
- SUNDR 本质是把 Git 这个思想用到了网络文件系统。

---

## 5. FAQ

**Q: SUNDR 能防服务器不响应吗？**
A: 不能。它只保证"服务器撒谎/分叉可被检测"，不保证可用性。

**Q: 这和区块链有什么区别？**
A: SUNDR 是单服务器、客户端签名；区块链是多节点共识、PoW/PoS。SUNDR 是"可信客户端 + 不可信服务器"，区块链是"部分节点不可信"。
