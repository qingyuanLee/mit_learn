# FaRM: Fast Remote Memory (2015) 精读

> 论文：<https://pdos.csail.mit.edu/6.824/papers/farm.pdf> ｜ 对应 LEC 13（Optimistic Concurrency）

---

## 1. 一句话问题

**传统分布式系统每次写要走网络 + fsync，延迟几十毫秒。但现代数据中心 RDMA 网络可以让一台机器直接读写另一台机器的内存（微秒级），怎么利用这个特性造一个"内存级快"的分布式事务系统？**

---

## 2. 核心思路：乐观并发控制（OCC）+ 主存复制

- 数据全部放在 DRAM 里，**没有磁盘**。
- 每个数据项有一个**版本号**。
- 事务分两阶段：
  1. **读阶段**：乐观地读，不阻塞其他事务；
  2. **校验阶段**：commit 前检查自己读的数据在这期间是否被别人改了；
  3. 没改就 commit，改了就 abort 重试。
- 用 **2-copy** 复制（不是 3/5 副本），因为 DRAM 坏的概率远低于磁盘。

---

## 3. 为什么快？

| 传统系统 | FaRM |
|---|---|
| 每次写要 fsync | 数据在内存里，无 fsync |
| 走 TCP/IP 协议栈 | RDMA，微秒级 |
| 悲观锁（先加锁再操作） | 乐观并发（读时不加锁，commit 时校验） |
| 3-5 副本 | 2 副本，因为 DRAM 可靠 |

---

## 4. 与 Spanner 的对比

| | Spanner | FaRM |
|---|---|---|
| 存储 | 磁盘 + Paxos | 全内存 + RDMA |
| 一致性 | 外部一致 | 线性一致（单分区） |
| 事务 | 2PC + commit wait | OCC + 版本校验 |
| 延迟 | ms 级 | **微秒级** |
| 持久性 | ✅ 磁盘持久化 | ❌ 掉电丢数据 |

> FaRM 是"快到极致但不持久"；Spanner 是"跨洲强一致但慢"。两个极端。

---

## 5. FAQ

**Q: OCC 和 2PC 有什么区别？**
A: 2PC 是悲观的，先锁再操作；OCC 是乐观的，读时不加锁，commit 时校验冲突。

**Q: FaRM 掉电了怎么办？**
A: 论文里就是丢数据；FaRM 定位是"缓存层"或"内存级数据库"，不替代持久存储。

**Q: RDMA 是什么？**
A: Remote Direct Memory Access，绕过内核和 TCP 栈，直接网卡读写远端内存，延迟从几十微秒降到几微秒。
